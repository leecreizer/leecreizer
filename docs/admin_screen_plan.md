# 설계 어드민 화면 기획서 (쿠홈 설계프로그램 스타일)

유통 채널별로 설계 페이지에 노출할 카테고리/콘텐츠/태그를 관리하는 어드민 시스템.

- 실행: `pip install flask` 후 `python run_admin.py` → http://localhost:5050
- 초기 계정: `admin / admin1234`
- 데이터: SQLite (`admin/admin.db`, 최초 실행 시 자동 생성 + 예시 데이터 시드)

## 전체 구조

```
로그인 ─ 대시보드
          ├─ 채널 · 그룹 · 사용자   (요구 #2, 관리자 전용)
          ├─ 카테고리 관리          (요구 #3)
          ├─ 콘텐츠 관리 워크스페이스 (요구 #3+#4+#5 통합)
          ├─ 마스터 일괄등록        (요구 #6)
          ├─ 태그 마스터            (요구 #7)
          └─ 공개 API               (설계 페이지 연동)
```

데이터 관계:

```
채널(channels) ─┬─ 사용자그룹(user_groups) ── 사용자(users)
                └─ 카테고리 노출(category_channels)
카테고리(categories, parent_id 계층) ── 콘텐츠(contents) ── 마스터(content_master)
태그폴더(tag_folders) ── 태그(tags) ── 콘텐츠-태그 매핑(content_tags)
```

## 디자인 시스템 — "Soft Floating"

레퍼런스(라이트 글래스모피즘 플래너 UI) 기반.

- 쿨 그레이 그라데이션 배경 위에 떠 있는 라운드(22~24px) 화이트 패널
- 사이드바는 본체에서 분리된 플로팅 글래스 카드, 활성 메뉴는 **네이비 블랙 다크 타일**
- 액센트는 색상이 아니라 **명도 대비**(다크 타일) 하나로 통일 — 주요 버튼, 선택 폴더, 선택 칩
- 상태 뱃지·태그 칩·검색 입력은 필(pill) 형태, 그림자는 멀리 퍼지는 소프트 섀도우
- 타이포: Pretendard(본문) + IBM Plex Mono(코드·치수·수치)
- 모바일 반응형, `prefers-reduced-motion` 대응, 키보드 포커스 링

## 1. 로그인 `/login`

| 항목 | 내용 |
|---|---|
| 입력 | 아이디, 비밀번호 |
| 검증 | 비밀번호 해시(pbkdf2) 비교, 비활성(중지) 계정 차단 |
| 동작 | 성공 시 세션 발급 → 대시보드. 미로그인 접근 시 로그인으로 리다이렉트(원래 경로 유지) |

## 2. 유통 채널별 사용자 그룹 관리 `/org` — 관리자 전용

한 화면 3단 구성: **채널 → 그룹 → 사용자**.

- **채널**: 코드/이름/설명/사용여부. 소속 그룹이 있으면 삭제 불가.
- **사용자 그룹**: 소속 채널 필수. 소속 사용자가 있으면 삭제 불가.
- **사용자**: 아이디/이름/비밀번호/권한/소속 그룹/사용여부.
  - 수정 시 비밀번호를 비우면 기존 유지. 마지막 관리자 계정은 삭제 불가.
- 권한 3종: **관리자**(전체) / **운영자**(조직 관리 외 전체) / **조회자**(읽기 전용 — 모든 변경 차단).

## 3. 카테고리 관리 `/categories` — 설계 페이지 노출 연동, 계층 구조

- 무제한 깊이 트리. 행마다 채널별 노출 칩(다크=노출), 정렬 ▲▼, +하위, 수정, 삭제.
- 수정 모달에서 **채널별 노출 체크박스** — 공개 API가 이 매핑을 그대로 반영.
- 순환 이동 차단, 콘텐츠 보유 시 삭제 차단(하위 포함).
- 폴더 CRUD는 콘텐츠 워크스페이스에서도 동일하게 가능 (이 화면은 노출 현황 한눈 보기용).

## 4·5. 콘텐츠 관리 워크스페이스 `/contents` — 원페이지

"폴더 만들기 → 폴더 선택 → 상품 등록 → 마스터 입력"이 화면 이동 없이 이어진다.

```
┌─ 폴더 트리 ─┐ ┌─ 상품 리스트 ──────────┐ ┌─ 마스터 패널 ─┐
│ 전체         │ │ 코드│이름(인라인)│상태(인라인)│ │ 기본 정보      │
│ 가구 ▸ 침실  │ │     │ [저장][마스터][삭제]   │ │ 마스터 정보    │
│   └ 침대 (1) │ │ ...                        │ │ 노출 태그      │
│ +폴더/✎/×   │ └────────────────────────┘ │ [닫기][저장]   │
└─────────────┘                              └───────────────┘
```

- **폴더 트리(좌)**: 클릭 시 하위 포함 필터링, 건수 표시, 호버 시 +하위/✎수정/×삭제.
- **리스트(중)**: **콘텐츠명·노출상태를 행에서 바로 수정** 후 행별 [저장].
  상태/키워드 필터, 내보내기·일괄등록·신규 등록 버튼.
- **마스터 패널(우)**: 코드 또는 [마스터] 클릭 시 같은 화면에 열림.
  기본정보 + 마스터(브랜드·가격·치수·재질 등) + 태그를 한 번에 저장,
  저장 후에도 폴더/선택 상태 유지. 패널이 열리면 리스트는 자동 압축.
- **신규 등록**: 폴더 선택 상태에서 [+ 콘텐츠 등록] → 패널이 신규 모드로 열리고
  해당 폴더가 카테고리로 자동 지정.
- `/contents/<id>/edit` 전체 페이지 폼도 유지(대시보드 바로가기용, 같은 파셜 사용).

## 6. 콘텐츠 마스터 일괄등록 `/contents/bulk` + 내보내기 `/contents/export`

- **템플릿 다운로드**: 예시 행 포함 CSV(UTF-8 BOM, 엑셀 호환).
- **업로드 규칙**: `콘텐츠코드` 기준 upsert / `카테고리경로`(`가구 > 침실 > 침대`) 자동 생성 /
  `태그`(`스타일>모던`) 자동 생성, 폴더 생략 시 "미분류" / 상태는 노출·숨김·작성중 /
  UTF-8(BOM) 우선, CP949 폴백.
- **결과 리포트**: 신규/수정/오류 건수 + 행 단위 오류 메시지.
- **내보내기**: 워크스페이스의 현재 필터 그대로 같은 컬럼 형식 CSV 다운로드 →
  수정 후 재업로드하면 **왕복(roundtrip) 일괄 수정**이 된다.

## 7. 태그 마스터 `/tags`

- **태그 폴더**(스타일/평형대/가격대 등) 단위로 태그(이름·색상·사용여부·사용 건수) 관리.
- 콘텐츠 매핑이 있는 폴더는 삭제 차단, 태그 삭제 시 매핑 함께 제거(확인 후).
- 워크스페이스 패널과 일괄등록 CSV가 이 마스터를 참조.

## 8. 설계 페이지 연동 공개 API (읽기 전용, 인증 불필요)

어드민에서 "노출"로 설정한 데이터만 내려간다.

### `GET /api/channels/<채널코드>/categories`
채널별 노출 카테고리 트리. 상위가 미노출/비활성이면 하위도 제외.
```json
{ "channel": {"code": "DIRECT", "name": "자사몰"},
  "categories": [{"id": 1, "name": "가구", "children": [...]}] }
```

### `GET /api/channels/<채널코드>/contents`
노출(published) 콘텐츠 + 마스터 + 태그.
파라미터: `category_id`(하위 포함) / `tag`(반복 지정 시 AND) / `q`(검색)
```json
{ "channel": {...}, "count": 2,
  "items": [{"code": "BED-001", "name": "...", "thumbnail_url": "...",
             "master": {"brand": "...", "price": 0, "width_mm": 0, ...},
             "tags": [{"folder": "스타일", "name": "모던", "color": "#3b82f6"}]}] }
```

## 공통 UX 규칙

- 좌측 플로팅 사이드바 + 현재 메뉴 다크 타일 하이라이트. 조회자/운영자에게는 권한 밖 메뉴 숨김.
- 추가/수정은 모달 또는 인라인/패널, 삭제는 confirm 후 POST.
- 처리 결과는 상단 플래시 메시지. 저장/삭제 후 항상 작업하던 화면(필터·선택 유지)으로 복귀.
- 참조 무결성 보호: 하위 데이터가 있는 항목은 삭제 차단하고 사유 안내.

## 향후 확장 후보 (확인 후 추가)

- 콘텐츠 이미지 파일 업로드(현재는 URL 입력)
- 공개 API 키 발급/검증 (현재는 노출 데이터만 내려가는 공개 읽기)
- 변경 이력(audit log)
- 콘텐츠 정렬 순서 드래그 변경
