# Polymarket 지연-엣지 측정 하니스 (읽기 전용)

스레드(@chesnyfcb)가 주장하는 "Binance ↔ Polymarket 지연 차익거래" 엣지가
**당신 환경에서 실제로, 비용 후에도 남는지** 0원 리스크로 검증하기 위한 도구.

> 읽기 전용이다. 주문 제출도, 개인키/API 키 입력도 하지 않는다.
> 절대 출처 불명 봇에 키/시드를 넣지 말 것.

## 무엇을 측정하나

1. **Binance 공정확률**: 현물 가격 → 디지털 옵션 근사로 "UP 확률" 추정
   `P(만기 ≥ 행사가) = Φ( ln(P/K) / (σ·√τ) )`
2. **Polymarket 시장확률**: 공개 CLOB 오더북의 중간값
3. **갭** = 공정확률 − 시장확률 (엣지 후보)
4. **순엣지** = 공정확률 − 체결 호가(ask) − 비용 (양수여야 이론상 수익)

## 사용법

```bash
# 합성 데이터로 시연/검증 (네트워크 불필요)
python run_polymarket.py simulate --lag 3 --spread 0.02 --cost 0 --plot out.png

# 라이브 기록 (네트워크 허용 환경에서만; 주문 안 함)
python run_polymarket.py record --symbol BTCUSDT --token-id <YES토큰ID> \
    --horizon 900 --interval 1 --duration 600 --out samples.csv

# 기록 분석
python run_polymarket.py analyze --csv samples.csv --plot out.png
```

## 정직한 해석 (중요)

시뮬레이션으로 확인되는 사실:

| 조건 | 양의 순엣지 비율 | 의미 |
|---|---|---|
| 지연 3s, 비용 0 | ~59% | 스레드가 파는 장밋빛 그림 |
| 지연 3s, 스프레드 0.04 + 비용 0.01 | ~22% | 비용 넣으면 급감 |
| **지연 0s** (엣지 없음) | ~28% | **노이즈만으로도 "양의 엣지"가 잡힘** |

→ 마지막 행이 핵심이다. **갭/엣지 양수 표본을 세는 것만으로는 속는다.**
이 시뮬레이션은 *완벽한 지연 + 무한 깊이 + 항상 중간가 체결*을 가정한 **상한선**이다.
현실에서는 다음이 엣지를 더 깎는다:

- **체결 가능성**: 싼 쪽(저평가 outcome)에 팔 상대가 없으면 못 산다
- **오더북 깊이**: 의미 있는 크기로 들어가면 가격이 밀린다(슬리피지)
- **당신의 실측 지연**: 콜로케이션된 프로 봇이 먼저 먹는다
- **경쟁**: 스레드도 인정 — 갭이 12s→2.7s로 줄어듦(군집 효과)

## 결론

이 하니스가 "엣지 후보 있음"을 줘도 그건 **시작점**일 뿐이다.
실거래 전 반드시: 라이브 기록(read-only) → 체결가능성/깊이 반영 → 페이퍼 트레이딩.
한 푼이라도 넣기 전에 *당신 인프라*에서 엣지가 살아남는지부터 증명할 것.
